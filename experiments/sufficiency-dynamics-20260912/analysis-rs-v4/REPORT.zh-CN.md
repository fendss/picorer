## 研究问题与主要结果

本实验研究一个问题：在逐步获取记忆的过程中，模型认为“信息足够”的程度，是否与当前证据包的完整程度一致，这种判断又与最终答案正确性有什么关系？

结果表明，**原生充分性分数 S 包含与证据获取有关的信息，但它不能单独证明证据包已经完整，也不能单独保证答案正确。** 随着包内标准证据增加，S 整体升高；与此同时，很多状态在包内标准证据尚不完整时就已经出现正 S。搜索预览提供了一个有数据支持的解释：模型能够在当前上下文中看到尚未进入证据包的事实。

在最终答案层面，证据包完整度与正确性有很强的关系。包内标准证据不完整时，正 S 与非正 S 对应的正确率都很低；包内标准证据完整时，正 S 才进一步对应更高的正确率。因此，现有结果支持 R 与 S 提供互补信息，但尚未验证 S 就是真实充分性的可靠替代量，也未证明搜索预览造成了错误停止。

## 1. 实验测量的对象

我们对同一组 100 道问题独立运行三次，得到 300 条轨迹、2,150 个决策状态。每个状态保留真实 agent context，并在两个运行相同权重的本地模型服务上测量 S。两个服务用于检查测量稳定性，不构成跨模型比较。全部轨迹完成了最终答案生成与评测，共答对 133 次，正确率为 44.3%。本报告只分析 R、S、原始上下文及最终答案正确性。

**R 是每个状态的证据包覆盖率。** 证据包在检索过程中持续存在和更新，并非只在最终回答时才出现。对状态 t，我们计算：

`R = 当前证据包中已匹配的标准证据条数 / 该题标准证据总条数`

同一条标准证据重复出现只计一次，无关内容不增加 R。R=0 表示包内没有匹配到标准证据，不代表证据包一定为空。R=1 表示标注的标准证据链全部被覆盖，也不代表模型一定理解了它们。

当前实现从此前成功 read 的结构化证据记录重建各状态的证据包内容，按保存的完整原文或精确片段匹配 gold statement；当前状态将要执行的 read，计入下一状态。Picorer 的账本会合并已读片段并保留旧证据，因此这里的累计读取口径用于重建每步证据包，而不是用最终包倒推全部状态。

**S 是同一状态上下文下的原生充分性分数。** 本报告使用“sufficient”相对“insufficient”的 logit margin。S>0 只表示在给定 finish 协议时更偏向“充分”。它不等于选择 finish 动作的概率，更不等于已经停止检索。搜索、读取、工作记忆等动作仍可能继续发生。

还需区分证据包和模型此刻看到的文本。证据包由程序持续维护；当前 observation 可以展示证据收据、搜索预览和工作记忆，而不重复展示包内全部原文。read 当轮展示的 passage、账本保存的 parent 内容以及最终回答输入，也不保证逐字相同。因此，R 衡量包内标准证据，S 则由完整 agent context 决定，两者测量对象存在明确区别。

统计时，两个副本先合并为一个状态。R–S 覆盖率图先在同一轨迹内合并重复 R 状态，再在同一道题内合并三轮，最后跨题目平均，避免长轨迹主导曲线。其余状态计数和转移分析会明确给出分母。不确定性范围按题目聚类重采样 5,000 次，保留同题三轮与状态间的依赖。

## 2. S 随证据包变完整而升高，但并不与 R 同步

首先，S 的测量非常稳定。两个服务在 2,150 个状态上的 S 相关系数为 0.9995；按 S>0 与 S≤0 二分，只有 14 个状态不一致，占 0.65%。后面的变化因此不太可能主要由副本间测量误差解释。但可复现性本身不证明 S 的语义有效性。

证据包越完整，模型总体越偏向充分。在按题目平衡的统计中，R=0 时平均 S 为 -1.28，R=0.5 时为 3.16，R=1 时为 6.00。图 1 展示了这种总体关系，同时保留不同覆盖水平上的不确定性。

![图1：充分性分数与当前证据包完整度](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/01-s-by-package-coverage.png>)

图 1｜同一覆盖水平先在轨迹内、题目内聚合，再跨题目平均。误差线是 95% 重采样范围。各点来自的题目集合不同，例如 R=1/3 主要来自三跳题，因此点与点之间不能解读为同一题的连续变化。

轨迹内分析也支持这一关系：控制归一化检索时间后，R 从 0 增加到 1 对应 S 平均增加 2.57，95% 范围为 1.83 到 3.30。这个结果说明 S 与证据包覆盖之间的关系，并不完全由“检索越往后，二者都越高”解释。它仍然是观察性关系，不能理解为主动加入完整证据必然造成相同幅度的 S 变化。

不过，正 S 经常早于包内标准证据的出现。300 条轨迹中，293 条至少出现过正 S，其中 241 条首次出现正 S 时 R 仍为 0。在同时出现过正 S、且后来包内含有标准证据的 283 条轨迹中，231 条是 S 先为正，43 条在同一状态发生，9 条是包内先含标准证据。两者的中位间隔为一个决策状态。

![图2：S为正与证据包获取事件的时序](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/02-s-and-package-timing.png>)

图 2｜横轴是状态序号除以轨迹总状态数；纵轴是在该进度前已经发生相应事件的轨迹比例，分母始终为 300。S 首次大于 0 的曲线明显领先包内标准证据完整的曲线。归一化进度用于回顾性比较，并不是线上可预知的剩余检索预算。

这不意味着 agent 在没有证据时已经选择结束。事实上，在尚未终止的 1,850 个状态中，有 985 个 S>0，模型随后仍继续执行动作。**“S 为正”和“停止检索”必须分开分析。**

## 3. 搜索预览能解释部分提前出现的充分性判断

为了理解 R 尚低时为什么会出现正 S，我们重新检查了全部冻结上下文，并只在搜索候选区段中匹配标准证据，排除同一消息中的 read 原文、工作记忆和证据收据。

在 293 个首次正 S 状态中，236 个当前搜索预览含至少一条可精确匹配的标准证据，占 80.5%。因此，R 尚低不能被等同于模型没有看到相关事实：事实可以先出现在搜索预览中，随后才通过 read 进入证据包。

若把此前候选预览中出现过的事实与当前包内证据取并集，首次正 S 时有 253 条轨迹只覆盖部分标准证据链，27 条覆盖完整链，13 条未匹配任何标准证据；另有 7 条轨迹始终没有正 S。这个并集只描述信息曾出现在候选预览或被保存在包中，不代表模型此刻仍看得到全部内容，更不能当成模型已经理解的事实集合。

相邻状态的变化给出进一步证据。我们把 1,850 次状态转移分成四组：没有新增标准证据、仅候选预览中新增标准证据、包内新增此前已匹配的证据、包内新增此前未匹配的证据。后两组的区别在于：新增到包里的事实，此前是否已在累计候选预览或包内被匹配过。

控制前一状态的 S、R、检索时间及其平方项、题目跳数和实验轮次后，相对“没有新增标准证据”的转移，三组分别对应 S 额外增加 2.33、2.11 和 2.18。三组的 95% 范围均高于 0，且彼此大幅重叠。

![图3：不同证据获取事件与S的局部变化](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/05-evidence-gain-response.png>)

图 3｜点为回归调整后的组间差，横线为按题目重采样的 95% 范围。预览新增组含 498 次转移，其余两组分别含 372 和 75 次；参照组含 905 次。

这说明仅在预览中出现新事实，也与明显的 S 上升相伴。三组量级接近，但本分析没有进行等效性检验，不能声称预览和入包的作用完全相同，也不能据此证明前者导致了后者的变化。

S 的反转同样与当前预览有关。300 条轨迹中有 77 条在 S 为正后又出现非正值，占 25.7%。仅看前一状态 S>0、当前 R 仍不完整的转移，当前预览未匹配标准证据时，反转率为 80/507，即 15.8%；当前预览匹配到标准证据时，为 14/237，即 5.9%。

![图4：当前预览与S反转](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/04-preview-and-s-reversal.png>)

图 4｜分析限于上一状态 S 为正且当前 R 不完整的转移。横轴和反转结果都按当前状态确定。误差线为问题级 95% 重采样范围；两组比例未经协变量调整。

预览可见性可能与工具类型、前一状态 S 大小及上下文更新共同变化。因此，这里能够成立的是“当前预览与 S 的变化有关”，而不是“预览消失必然造成反转”。

## 4. 证据包完整时，S 才表现出明显的额外正确性信息

前面的分析考察轨迹过程；接下来只使用每条轨迹的终止状态，因为现有正确性评分只对应最终答案。

表 1｜按终止状态的 R 与 S 分组的答案正确率。

| 证据包标准证据 | S 状态 | 轨迹数 | 答对数 | 正确率 |
|---|---|---:|---:|---:|
| 不完整 | S≤0 | 29 | 1 | 3.4% |
| 不完整 | S>0 | 98 | 5 | 5.1% |
| 完整 | S≤0 | 10 | 3 | 30.0% |
| 完整 | S>0 | 163 | 124 | 76.1% |

![图5：终止证据包完整度与充分性分数共同关联正确率](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/08-terminal-evidence-gate.png>)

图 5｜包内标准证据不完整时，两组正确率都很低；完整时，S>0 组对应更高正确率。连线只帮助比较两个 R 条件，并不表示同一条轨迹接受了干预。

在 R 不完整时，正 S 相对非正 S 只对应 1.7 个百分点的正确率差，95% 范围为 -6.6 到 8.8；在 R 完整时，差值为 46.1 个百分点，范围为 19.7 到 75.5。两种 R 条件下的差异再相减，为 44.4 个百分点，范围为 16.9 到 73.7。这支持 S 的正确性信息随证据包完整度而变化。

但 R 完整、S≤0 的组只有 10 条轨迹，所以 46.1 个百分点的具体大小仍不稳定。更直接的观察是：R 完整且 S>0 的正确率，在三次独立运行中分别为 76.3%、76.5% 和 75.5%。

还可以利用三次运行进行同题比较，减少固定题目难度的影响。36 道题在不同运行中出现过“R 完整”和“R 不完整”两种终止结果，共形成 72 个运行对。42 对中，不完整运行答错、完整运行答对；27 对都答错；3 对都答对；样本中没有出现不完整运行答对而完整运行答错的运行对。

![图6：同一道题不同运行中的证据完整度与答案结果](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/09-within-question-pairs.png>)

图 6｜行是同题 R 不完整运行的结果，列是 R 完整运行的结果。72 个运行对并非 72 个独立问题，不确定性仍按题目聚类。

完整运行相对不完整运行的配对正确率差为 58.3 个百分点，95% 范围为 43.1 到 73.6。这表明总体关系不能只归因于“容易题更容易取齐证据”。不过，运行之间还可能同时改变了查询质量、工具调用和推理状态；这些不是对同一状态主动补证据的实验，不能把结果写成“补齐证据造成了正确率提升”。

## 5. R 与 S 的互补性有多大

为了把二者的互补性表达得更直观，我们对已有的 300 个最终答案进行回顾性排序，比较保留相同比例答案时的正确率。三种排序分别是：只按 S、只按 R、先把 R 完整的答案排在前面再按 S 排序。并列分数按随机打破并列的期望正确率处理。

当保留前 25%，即 75 个答案时，正确率分别为 64.0%、73.4% 和 82.7%。增加“只按 R”的参照后可以看到，组合结果既受益于标准证据完整度，也受益于完整组内部的 S 排序。所有答案全部保留时，三条曲线都回到总体正确率 44.3%。

![图7：R与S的回顾性排序比较](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/07-oracle-ranking.png>)

图 7｜三种排序使用同一组已完成的最终答案。含 R 的方法使用 benchmark gold 标注，是已知标准证据时的诊断性比较；曲线是样本点估计。

**这不是可以直接部署的停止策略。** 真实使用时通常没有 gold evidence，无法直接计算这里的 R；现有数据也没有为每个中间状态生成独立答案。图 7 支持的是 R 与 S 含有互补信息，不能声称组合后已把系统总体正确率提高到 82.7%，也不能声称提前停止会保留同样收益。

## 6. 当前可以成立的结论与边界

这些分析给出一条一致的证据链：S 可以稳定测量，并且随证据获取总体上升；但它经常在证据包覆盖尚低时就为正，而且正值并不意味着实际结束检索。分开检查候选预览后发现，许多这样的状态已经在当前上下文中看到了部分标准事实，预览中的事实变化也与 S 的变化相关。最终，证据包完整度与答案正确性强相关，而 S 在证据完整的终止状态中提供额外区分信息。

因此，最合适的解释是：**S 反映模型在给定上下文和 finish 协议下表达的充分性倾向；R 描述当前证据包对标准证据的覆盖。二者相关，但不可互换。** 将二者与最终正确性放在一起，比单独宣称 S 是“好的”或“坏的”充分性代理更符合当前证据。

报告没有把搜索预览确定为错误的因果来源。要验证这一解释，需要在同一个冻结状态上控制预览是否显示、包内证据是否保留，重新测量 S，并在相应证据条件下生成答案。当前结果只用于定位这样的干预对象。

还需保留三个范围限制。第一，标准证据采用精确文本匹配，未匹配不等于不存在同义或替代证据，完整匹配也不等于模型已理解。第二，36 道题的标准证据涉及数据版本冲突；旧分析在其余 64 道题上仍观察到正向 R–S 关系，但不能据此把所有正确性和预览结果都视为已经完成冲突敏感性验证。第三，三次运行只覆盖一个模型和一个任务集合，不能推出跨模型、跨任务普遍成立。

## 修订与复现说明

本报告取代此前按十项分析顺序组织的解释性报告。主要修订如下：

- R 统一指每个状态的当前证据包覆盖率，不再写成只属于最终回答的“已提交证据”。
- 搜索预览重新按候选区段提取；旧脚本会把同一工具消息中的 read 原文或工作记忆混入匹配。全部 2,150 个状态已重新审计。首次正 S 时当前预览匹配率由旧值 93.5% 修正为 80.5%，反转分组也已重算。
- 二元副本差异按 S>0 计算，修正为 14/2,150，即 0.65%；旧值约 1.0% 来自把零值单列的三分类符号比较。
- 不采用旧报告中“预览解释度是证据包的四倍”这一归因。旧特征组存在交叉项和包内证据重叠，不能解释为干净的独立贡献。
- 正确率差使用原样本点估计，而非 bootstrap 均值；图 7 补充只按 R 排序的参照，并明确其依赖 gold 标注。
