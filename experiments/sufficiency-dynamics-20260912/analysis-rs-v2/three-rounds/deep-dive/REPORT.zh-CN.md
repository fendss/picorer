# Picorer 充分性信号的失配机制

> 历史探索版：本报告的预览提取口径和机制解释已修订。请引用 [2026-09-14 完整报告](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v4/REPORT.zh-CN.md>)；旧版预览匹配率与因果结论已撤回。

## 结论先行

上一版分析把问题概括成“R 与 S 有关系，但 S 会过早升高”。这个结论过于表面，因为它把 R 当成了模型已经看到的全部证据。重新检查 2,150 个原始 agent context 后发现：

- 当前的 R 只统计经过 `read`、最终可交给回答阶段的证据；
- agent 在做检索决策时还会看到 `search` 返回的文本预览；
- 这些预览可以触发正的充分性信号，却不会自动进入最终 evidence handoff。

因此，最重要的现象不是简单的“模型没有证据却自信”，而是一个更具体的系统失配：**S 衡量的是 agent 对当前可见信息的主观充分感，而答案正确性依赖的是已经正式提交给回答阶段的证据。**

这使 R 和 S 更像两个互补条件：R 回答“关键证据是否已经被可靠地取回并提交”，S 在 R 已经完整时进一步反映“模型是否认为这些证据足以作答”。

## 1. S 为什么看起来升得太早

我们定位了每条轨迹第一次出现正 S 的状态。300 条轨迹中，293 条至少出现过一次正 S。

如果只看 `read` 提交的证据，241 条轨迹在 R 仍为 0 时就第一次出现正 S，表面上像是严重的无证据自信。但把当前 context 中模型实际可见的搜索预览也纳入检查后，解释发生了明显变化：

- 293 个首次正 S 状态中，274 个当前搜索预览里已经出现至少一条可精确匹配的 gold evidence；
- 按“此前搜索预览中见过的证据 + 已 read 的证据”计算，只有 13 条轨迹在完全没有匹配到 gold evidence 时变成正 S；
- 253 条轨迹是在只看到部分 gold evidence 时变成正 S；
- 27 条是在已经看到完整 gold chain 时变成正 S；
- 另有 7 条轨迹始终没有正 S。

![首次正 S 时，已提交证据与实际可见证据的差异](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v2/three-rounds/deep-dive/11-first-positive-evidence.png>)

**图 1｜首次正 S 的证据状态。** 上条只统计经过 `read` 的证据，因此 80.3% 看起来没有 gold evidence；下条加入搜索预览后，84.3% 实际已经见过部分 gold evidence，真正完全没有匹配证据的只占 4.3%。

这个结果否定了一个过强解释：我们不能说 S 主要是“在没有任何证据时产生的虚假充分感”。更准确的说法是：**S 对部分证据、以及尚未提交的搜索预览非常敏感；它通常在完整 gold chain 被正式提交之前就会转正。**

需要注意，预览匹配采用严格的标准化文本匹配，因此“见过 gold evidence”的比例是保守下界。另一方面，累计预览把此前出现过的文本视为模型曾经见过，不代表模型始终保留了这些信息。最直接、不依赖这一假设的证据仍然很强：首次正 S 时，93.5% 的状态在当前预览中就含有至少一条 gold evidence。

## 2. 真正的风险在 evidence handoff

搜索预览会影响 agent 的充分性判断，但它不会自动成为最终答案模型的输入。只有经过 `read` 的内容才进入正式 evidence handoff。

这造成了一种危险状态：agent 因搜索预览而觉得信息已经足够，于是结束检索；但回答阶段收到的正式证据仍然不完整。

在 300 个终止状态中：

- 127 个终止状态的已提交证据不完整；其中 98 个 S 为正，但只有 5 个答案正确，正确率为 5.1%；
- 173 个终止状态的已提交证据完整；其中 163 个 S 为正，124 个答案正确，正确率为 76.1%；
- 还有 10 条轨迹虽然已提交证据不完整，但把历史搜索预览也算上后曾经见过完整 gold chain；这 10 条中 9 条 S 为正，最终却只有 1 条答对。

最后这一组是 preview–handoff gap 的直接案例：信息曾经出现在 agent 的视野中，足以让 S 转正，却没有被可靠地提交给答案阶段。

## 3. R 是门槛，S 在门槛之后才有明显价值

终止状态按 R 是否完整、S 是否为正分成四组：

| 已提交证据 | S 状态 | 数量 | 答对 | 正确率 |
|---|---:|---:|---:|---:|
| 不完整 | S 不为正 | 29 | 1 | 3.4% |
| 不完整 | S 为正 | 98 | 5 | 5.1% |
| 完整 | S 不为正 | 10 | 3 | 30.0% |
| 完整 | S 为正 | 163 | 124 | 76.1% |

![终止状态中 R 与 S 对答案正确率的共同作用](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v2/three-rounds/deep-dive/12-terminal-evidence-gate.png>)

**图 2｜终止状态的证据门槛。** 当已提交证据不完整时，S 转正几乎不能提高正确率；当已提交证据完整时，正 S 对应的正确率明显更高。

按题目进行 5,000 次聚类重采样后：

- 在 R 不完整的状态中，正 S 与非正 S 的正确率只差 1.7 个百分点，95% 重采样范围为 -6.7 到 8.9；
- 在 R 完整的状态中，两者相差 46.1 个百分点，95% 重采样范围为 18.0 到 75.4；
- 两种 R 条件下的差异再相减，交互差为 44.4 个百分点，95% 重采样范围为 15.2 到 73.9。

正 S 且 R 完整这一组的结果在三次独立运行中也很稳定：正确率分别为 76.3%、76.5% 和 75.5%。

这支持一个比“R 和 S 都有用”更具体的解释：

1. **R 是证据可用性的门槛。** 关键证据没有正式提交时，模型的充分感不能挽救答案。
2. **S 更像门槛之后的准备度信号。** 当 gold evidence 已经完整提交后，S 仍能区分模型是否可能正确使用这些证据。

这仍然是观察性结果，不应直接解释成因果效应。特别是“R 完整但 S 不为正”只有 10 个终止状态，组别较小。不过，在 R 完整的 173 个状态内部，连续 S 预测正确性的 AUC 为 0.665，按题目重采样的 95% 范围为 0.568 到 0.756，也说明结果不只由正负阈值造成。

## 4. 显式 J 不能作为 S 的可靠真值

J 原本被设计成对同一状态重复询问“证据是否充分”，用显式回答来验证原生 S。但数据表明，J 本身存在极强的回答偏置。

最清楚的对照是每条轨迹的第一个状态。此时 agent 还没有执行任何检索：

- 原生 S 为正的比例是 0%；
- 101 次显式判断的多数票却在 99% 的状态上回答“sufficient”；
- 每个状态回答“sufficient”的平均比例为 82.7%。

![原生 S 与显式 J 在不同状态集合中的阳性率](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v2/three-rounds/deep-dive/13-explicit-j-bias.png>)

**图 3｜显式 J 的回答偏置。** 在尚未检索的初始状态，J 已经几乎全部判为充分，因此它不能被当作独立真值来校验 S。

在全部 2,150 个状态上，J 的多数票有 92.7% 为“sufficient”，而原生 S 只有 58.0% 为正。两者的符号一致率为 63.0%，连续值相关系数为 0.480。这些数字不能证明 S 错了，只能说明 J 没有提供一个可信的独立参照。

因此，当前数据不支持论文中“先用 J 验证 S，再把 S 当成非侵入式 proxy”的原始论证。更稳妥的做法是把 J 降级为一种受到 prompt 影响的行为读数，把 S、R 和答案正确性放在同一观察框架中，而不是指定其中任何一个为充分性的真值。

## 5. S 也不是单调累积量

如果 S 表示随证据逐步积累的单一充分性状态，转正后通常不应频繁退回负值。但 300 条轨迹中：

- 216 条表现为一次性从负转正，之后不再转负；
- 77 条在转正后至少有一次重新变成非正，占 25.7%；
- 7 条始终没有转正。

![轨迹中原生 S 符号变化类型](</Users/johnnychiu/Documents/memory harness from the first principle/picorer/experiments/sufficiency-dynamics-20260912/analysis-rs-v2/three-rounds/deep-dive/14-native-sign-reversals.png>)

**图 4｜S 的符号反转。** 四分之一轨迹会在“已经充分”和“仍不充分”之间反复变化，说明 S 还受到当前工作记忆内容、搜索结果替换和上下文组织方式的影响。

这与 preview–handoff gap 的解释一致：S 并非只响应累计取回了多少 gold evidence，也会响应当下 context 中哪些信息最显眼、哪些预览仍然存在，以及模型是否能把它们组织成可回答的问题表征。

## 6. 现在能够成立的结论

基于现有三轮数据，最稳妥的结论是：

> Picorer 的原生 finish margin 不是 gold-evidence completeness 的等价替代，也没有被显式 J 有效验证。它更接近 agent 对当前可见上下文的主观作答准备度。这个信号经常被尚未提交的搜索预览触发，并且只有在关键证据已完整提交时，才与最终答案正确性表现出稳定关系。

这给出一个具体的系统诊断，而不只是一个相关性现象：**检索 agent 的观察空间与答案模型的 evidence handoff 空间不一致。** 当前 finish 决策允许 agent 根据预览停止，但下游答案阶段不能保证获得触发停止的那部分信息。

## 7. 下一步实验应该检验什么

下一步不需要继续堆更多相同轨迹，最有价值的是做一个受控干预，直接检验 preview–handoff gap：

1. **Preview-only：** 保持当前系统，让搜索预览影响 agent，但不进入答案输入。
2. **Commit-before-finish：** 一旦 agent 选择 finish，自动把支持该决定的预览对应文档执行 `read` 后再回答。
3. **Preview-to-answer：** 不补 `read`，直接把触发 finish 的最后搜索预览一并交给答案阶段。
4. **Read-only finish：** 计算 finish margin 时隐藏搜索预览，只允许它依据已经提交的证据判断。

四个条件使用相同问题、相同检索随机种子，并同时比较终止时已提交 R、答案正确率和 S。若第 2 或第 3 个条件显著修复“R 不完整但 S 为正”的低正确率，就能直接证明当前主要问题来自 handoff，而不是 S 本身完全没有意义。

## 数据范围与复现文件

- 3 次独立运行，每次 100 题；
- 300 条完整轨迹，2,150 个冻结决策状态；
- 每个状态有两份独立副本，每份包含 101 次显式 J 采样；
- J 采样总数为 434,300；
- 搜索预览审计覆盖全部 2,150 个原始 request context；
- 总体最终正确率为 133 / 300，即 44.3%。

主要分析产物：

- `deep-analysis-summary.json`：本文全部汇总统计；
- `states-with-visible-context.csv`：逐状态的 read coverage、当前预览和累计预览覆盖；
- `trajectory-crossings.csv`：逐轨迹首次正 S 与符号反转；
- `terminal-gate.csv`：终止状态的 R、S 与答案正确性；
- `explicit-j-bias.csv`：J 与 S 在不同状态集合中的阳性率。
